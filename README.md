## Data sources

- **openFDA Drug Enforcement API** — https://open.fda.gov/apis/drug/enforcement/ (public, U.S. FDA)
- **FCA published fines** — https://www.fca.org.uk/news/news-stories/2025-fines (and 2024, 2023)
- **Deviation dataset** — synthetic, generated by `scripts/generate_data.py`. No confidential or employer data is used anywhere in this portfolio.

The FCA dataset is validated by reconciling computed annual totals against the FCA's own published figures. All three years match exactly.

## Reproducing the analysis

```bash
python scripts/generate_data.py   # rebuilds the synthetic deviation dataset
python scripts/fetch_fda.py       # re-fetches live FDA data from openFDA
python scripts/analyse_fca.py     # validates and summarises FCA fines
```

No dependencies beyond the Python standard library. Charts render client-side with Chart.js from CDN.

## Viewing locally

The pages load data via `fetch()`, which browsers block over `file://`. Run a local server:

```bash
python -m http.server 8000
```

Then open http://localhost:8000

## Publishing to GitHub Pages

You have a GitHub account, so this takes about ten minutes.

### 1. Create the repository

Go to https://github.com/new and create a repository named **`portfolio`**. Set it to **Public** (GitHub Pages needs public on free accounts). Do not tick "Add a README" — this folder already has one.

### 2. Upload the files

On the new empty repository page, click **uploading an existing file**.

Drag in **the contents of this portfolio folder** — that means `index.html`, the other HTML files, `README.md`, and the `assets`, `data`, and `scripts` folders. Do not drag the `portfolio` folder itself, or your URLs will end up with an extra `/portfolio/` in them.

Scroll down, write "Initial portfolio" in the commit box, and click **Commit changes**.

### 3. Turn on GitHub Pages

In the repository, go to **Settings** → **Pages** (left sidebar).

Under "Build and deployment", set **Source** to `Deploy from a branch`, **Branch** to `main`, folder to `/ (root)`. Click **Save**.

### 4. Wait, then visit

Give it two to three minutes, then go to:

```
https://YOUR-USERNAME.github.io/portfolio/
```

If you see a 404 at first, wait another minute and refresh — the first build takes a little longer.

### 5. Finish the details

Two things to update once it is live:

- In `index.html`, replace the placeholder LinkedIn link (search for `Add your LinkedIn URL here`) with your actual profile URL.
- In this README, replace `YOUR-USERNAME` in the live site link above.

You can edit files directly on GitHub — click the file, then the pencil icon.

## Using this in your job search

**On your CV**, add the URL under your contact details, on the same line as your email and LinkedIn.

**On LinkedIn**, add it to the Featured section on your profile, and to the Website field in Contact Info.

**In applications**, reference a specific project rather than the portfolio generally. For a pharma QA role: "I built a deviation and CAPA dashboard demonstrating how I track quality KPIs — it's in my portfolio at [link]." For a financial services compliance role, lead with the FCA analysis instead, since it shows you have done the reading on a sector you are moving into.

**In interviews**, the deviation dashboard is the one to talk through. It maps directly onto work you have actually done, and the CAPA recurrence finding gives you a concrete answer to "why does CAPA matter" that is grounded in analysis rather than assertion.

One honest note worth being ready for: the deviation dataset is synthetic, and you should say so unprompted if the topic comes up. Framing it as "I couldn't use employer data, so I built a dataset that mirrors the structure" is a point in your favour — it shows you understand confidentiality. The FDA and FCA analyses use entirely real published data, so lead with those if you want to demonstrate working with genuine regulatory sources.
